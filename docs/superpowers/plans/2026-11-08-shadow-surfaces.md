# Shadow DOM 分批迁移

## 目标与基线

构画自有界面采用 Shadow DOM 隔离。统一挂载、样式、主题和事件约定，再按界面位置分批实施。

第一批基于 4.1.6，在独立工作区完成后合入 4.1.8。后续批次从 4.1.8 继续。

| 第一批 | 悬浮球 | 已合入 4.1.8 |
| 第二批 | 自绘 Toast 与导入进度浮层 | 本地构建与验收通过，待用户测试 |
| 第三批 | 楼内框的构画内容 | 待实施 |

## 统一约定

- 外部 host 承担挂载、定位和宿主交互，内部按钮与内容放入自己的 Shadow Root。
- 复用现有版本化样式地址和主题 token，控件声明自己的尺寸、盒模型与文字基线。
- 跨根读取通过明确的组件查询入口，事件绑定到所属根。需要向外通信时使用明确接口。
- 楼内保留可被酒馆识别的外壳，内部内容隔离。折叠、重绘、主题、用户名遮罩与收藏捕获逐项适配。
- 自绘 Toast 的隔离与第三方 Toast 接管共用现有调用入口。

## 第一批实施

1. 在 `index.js` 增加悬浮球按钮查询入口，统一返回 host 的 Shadow Root 内按钮。
2. `injectFab()` 创建独立 Shadow Root，加载现有 `STYLESHEET_URL`，将品牌按钮放入根内。
3. 忙碌态、生成态、主题同步和手势绑定使用该查询入口。外部 host 继续负责显示、定位与位置保存。
4. 在 `style.css` 补齐悬浮球自己的控件基线，目标为 36px、透明底、当前描边与圆环笔图标。
5. 增加针对真实按钮查询和状态更新的回归用例，运行生产构建与隔离浏览器验证。

## 第一批验收

- 页面全局的按钮、圆角、字体、边框和内边距规则无法匹配内部按钮。
- 亮暗与自动主题、界面字号、忙碌与完成状态正常。
- 点击开关、桌面拖动与位置恢复、手机视口切换、置顶层级正常。
- 原有完整测试通过，生产构建使用正确资源地址。
